## 本机开发版 · 新对话保存与恢复

开发分支为 `haven/local-chat-storage`。在仓库根目录用 Node 24 运行 `npm run chat:local`，在这台电脑上打开 `http://127.0.0.1:4190/chat/`。默认数据库为 `.haven-local/room.sqlite`，保存在构建目录之外，Git 与部署均忽略此目录。服务只监听本机，重启时沿用同一数据库。

- 每次发送先保存 Iris 的消息，再生成和保存模拟回复及模型来源。相同发送编号可安全重试。公开 M1 预览继续走离线样板。
- Gateway 从当前会话读取最近的完整轮次，带上双方角色、当前消息与用户选择的模型，交给模型适配器。当前上限为前 12 轮，受 24000 字符的上下文预算约束，当前输入始终保留。重新生成旧回复时，只带到当时那一轮。数据库保留完整会话。
- 本机适配器使用合成回复。例如先说「我们读到第 18 页了」，重新打开后问「昨天读到哪儿了？」，模拟器从传入的上下文中找页码。真实模型线路与凭据另行确认。
- 金金确认 Ombre 已经使用本地 BGE-M3。后续长期记忆检索沿用 Ombre MCP 和已有索引。当前续聊直接从聊天数据库读取最近发言。

已用合成数据验证关闭聊天标签、重启服务、模拟次日重开和继续追问。浏览器模拟发送回执丢失后，点重试只保存一轮。测试使用单独的临时数据库。

### 已实现的本机入口

- 首页点「日记」或具体日期进入 `/diary/`。月历下方可添加、勾选、删除当天待办并编辑纸便签，复用首页原有的按日浏览器存储。可切换日期、月份或回到今天。输入框点按保留原有边框。
- 本机聊天中输入「查旧聊天：想查的内容」才会检索。当前会话的原消息按段计算向量，按文字和语义评分，再用消息编号和字符范围核对原文。点回复下的来源编号可跳回对应消息。普通聊天继续走最近上下文。
- `/app/archive/search`、`/app/archive/read` 用于查找、核对原话。`/app/archive/bind` 与 `/app/archive/evidence` 将记忆编号与引用时的消息快照保存在小屋本机数据库。回复重生成后仍可查出来源发生过变化。当前可查的是本机聊天库，真实旧导出和 Ombre 存量记忆仍独立。
- 本地向量服务支持 Ollama 或兼容的回环嵌入端点。若 Ollama 仅在本机 Docker 内运行，可在 Git 忽略的 `.haven-local/embedding.env` 指定 `HAVEN_EMBEDDING_CONTAINER` 和 `HAVEN_EMBED_MODEL`。运行 `npm run chat:local` 时读取这些设置。向量服务不可用时，页面提示此次只使用文字检索。

### Serein 源码对照

核对作者后续项目 Serein 的 `fdab5a8`。适合小屋借鉴的有三处。

- **先找记忆，再核原话。** 自动召回对 Scene／Event 做混合检索并重排。命中后，`read_memory(with_evidence=True)` 可以取回该记忆实际绑定的原话。建议保留记忆编号到原消息编号的关联。[召回与证据读取](https://github.com/Yinglianchun/Serein/blob/fdab5a8af8c966572c47faabed18223079bc91c4/README.md#L78-L90) · [证据测试](https://github.com/Yinglianchun/Serein/blob/fdab5a8af8c966572c47faabed18223079bc91c4/tests/test_hook_evidence_on_demand.py#L29-L46)
- **独立查阅原话。** 启用原话工具后，`source_message_search` 对正文使用 SQLite 字面匹配，可按日期和角色过滤。`source_message_read` 按编号取全文，归属明确时可取同一来源会话前后各最多三条。历史文件默认只归档。小屋若要靠改写的问句搜到从未整理成记忆的消息，仍需给原话片段建立语义检索。[查原话与邻文](https://github.com/Yinglianchun/Serein/blob/fdab5a8af8c966572c47faabed18223079bc91c4/src/serein/compat/originals.py#L79-L159)
- **分批导入。** 借鉴文件预览、稳定消息编号去重、同号异文报冲突，以及沿当前节点回溯分支。多分支且缺当前节点时，Serein 会提示无法确定，只导入当前分支也意味着其他版本要另行保留。小屋的完整分支归档仍需单独设计。[解析代码](https://github.com/Yinglianchun/Serein/blob/fdab5a8af8c966572c47faabed18223079bc91c4/src/serein/imports.py#L56-L71) · [导入约定](https://github.com/Yinglianchun/Serein/blob/fdab5a8af8c966572c47faabed18223079bc91c4/docs/file-imports.md#L10-L26)

### Haven-Ombre 源码对照

只读参考 Yinglianchun 的 Haven-Ombre，版本 `2746223`。作者已停止维护该仓库。新增代码的使用范围及署名要求见 [NOTICE](https://github.com/Yinglianchun/Haven-Ombre/blob/2746223f37f1da43195e7997b506b2bd6205a9b0/NOTICE.md)。本轮只记录设计取舍。

- 原文以消息为单位保存，带来源消息编号、会话、角色和时间，支持重复导入检测。其原文搜索走 SQLite FTS5 与字符串匹配。向量搜索使用问句向量对记忆桶排序。换一种说法寻找未写进桶的原话，仍需要为聊天片段建立可查的索引。[原文存储](https://github.com/Yinglianchun/Haven-Ombre/blob/2746223f37f1da43195e7997b506b2bd6205a9b0/raw_events.py#L119-L159) · [原文搜索](https://github.com/Yinglianchun/Haven-Ombre/blob/2746223f37f1da43195e7997b506b2bd6205a9b0/raw_events.py#L530-L565) · [桶向量搜索](https://github.com/Yinglianchun/Haven-Ombre/blob/2746223f37f1da43195e7997b506b2bd6205a9b0/embedding_engine.py#L192-L230)
- 可借鉴低证据时放弃召回，以及命中后回读来源前后文的做法。上游的来源窗口按记忆文件行号读取，小屋应按会话、消息和分支定位聊天原文。[来源窗口](https://github.com/Yinglianchun/Haven-Ombre/blob/2746223f37f1da43195e7997b506b2bd6205a9b0/source_refs.py#L7-L34)
- 上游 ChatGPT 解析器按时间展开消息树，仅输出角色、正文和时间。我们的分批导入要保留会话、消息及父节点编号，以便追加、去重，并正确区分重新生成的两个版本。[导入解析](https://github.com/Yinglianchun/Haven-Ombre/blob/2746223f37f1da43195e7997b506b2bd6205a9b0/import_memory.py#L129-L167)
